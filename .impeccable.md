# Idea Evolution design context

## Design Context

This brief is provisional until the project owner supplies a more specific visual direction.

### Users

The primary user is a technically capable researcher or creator exploring a large space of generated ideas on a local machine. They need to configure an evolution, follow its progress, compare candidates, inspect evidence, and understand why an idea survived. For artifact-producing runs, they also need to inspect visual output, source code, execution details, and evaluation evidence without losing the idea's evolutionary context.

### Brand Personality

Rigorous, exploratory, and calm. The product should feel like a trustworthy research instrument with an expressive visual-studio layer, not a generic SaaS dashboard or a playful content generator. It should encourage curiosity while keeping provenance, uncertainty, and failure states explicit.

### Aesthetic Direction

Light-first, information-dense but progressively disclosed, and oriented around the work rather than decorative chrome. The evolution tree, ranked comparison, and a shared persistent inspector are the core spatial model. Visual artifacts should be given generous, neutral viewing surfaces. Avoid generic indigo-gradient AI styling, nested cards, decorative metrics, and modal chains.

Accessibility target: WCAG 2.2 AA, keyboard-complete workflows, reduced-motion support, non-color encodings, and accessible textual/table equivalents for charts and visual evaluation state.

### Design Principles

1. **Evidence before decoration.** Scores must name their evaluator, units, direction, weight, status, and evidence. Failed or missing evaluations are never silently displayed as zero.
2. **One idea, one inspector.** Cards, tree nodes, and ranked rows select the same idea and use the same detail surface; deeper artifact, code, evaluation, and lineage views remain contextual and linkable.
3. **Progressive disclosure.** Overview surfaces show the primary artifact, selection score, and status. Source, logs, raw JSON, and evaluator traces load only when requested.
4. **Safe by construction.** Generated HTML, SVG, code, and links are untrusted. Artifact previews are origin-isolated or rasterized, source is escaped, and executable work never runs in the web process.
5. **Preserve scientific provenance.** Candidate text, producer version, source digest, execution profile, artifact digest, evaluator version, and aggregation formula remain traceable and reproducible.
6. **Adapt, do not amputate.** Narrow layouts stack comparisons and use a full-screen inspector; core history, artifacts, evaluation evidence, and voting remain available.
